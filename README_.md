# Tanzila Rahman — Academic Portfolio

A modern, static React portfolio for [Tanzila Rahman](https://scholar.google.com/citations?user=7GKKBLkAAAAJ&hl=en), Senior Research Scientist at Huawei Canada. Built with React, Tailwind, framer-motion and recharts; deployable to GitHub Pages.

## Project structure

```
/                     # React SPA (CRA + Tailwind)
  src/
    components/       # Navbar, Hero, About, Impact, Publications, News, Footer
    data/             # ← edit these to update content
      profile.js      # name, photo, bio, links, affiliations
      publications.js # paper list (filterable by category)
      news.js         # timeline entries
      scholar.js      # auto-generated by scripts/scrape_scholar.py
scripts/
  scrape_scholar.py   # Scholar → scholar.js generator
.github/workflows/
  deploy.yml          # build & publish to GitHub Pages on push to main
  update-scholar.yml  # weekly cron to refresh Scholar metrics
```

## Local development

```bash
npm install
npm run dev                # http://localhost:3000
```

## Updating content

Everything lives in `src/data/`:

| File | What to edit |
|---|---|
| `profile.ts` | Name, title, institution, bio, photo, social links, CV URL |
| `publications.ts` | Add/remove papers, change categories, add per-paper `image` |
| `news.ts` | Prepend a new entry at the top of the array |
| `scholar.ts` | **Auto-generated** — leave alone unless the workflow fails (see below) |

To add a real profile photo: drop a file into `public/` (e.g. `profile.jpg`) and set `profile.photo = "/profile.jpg"` in `profile.js`.

## Refreshing Google Scholar metrics

Two ways:

### 1. Automatically (GitHub Actions)

`.github/workflows/update-scholar.yml` runs **every Sunday at 06:00 UTC** and on manual dispatch. It:

1. Installs Python + the [`scholarly`](https://pypi.org/project/scholarly/) library.
2. Runs `scripts/scrape_scholar.py`.
3. Commits `public/data/scholar.json` only if metrics changed.

> ⚠️  Google Scholar aggressively rate-limits GitHub Actions IPs. The script is designed to **soft-fail** (exit 0 without writing) when blocked, so the workflow won't go red — but it also won't always succeed. Manual runs from your own machine are more reliable.

### 2. Manually

```bash
pip install "scholarly>=1.7" fake-useragent
python scripts/scrape_scholar.py
git add public/data/scholar.json
git commit -m "chore(scholar): refresh metrics"
git push
```

If Scholar blocks your IP, just edit `scholar.json` directly with the latest numbers — it's plain JSON.

## Deploying to GitHub Pages

`.github/workflows/deploy.yml` builds the React app and publishes it whenever `main` is updated.

**One-time setup in the repo:**

1. Go to **Settings → Pages → Build and deployment**.
2. Set **Source** to **GitHub Actions**.
3. (Optional) Add a custom domain.

After the first push to `main`, the site will be live at `https://<username>.github.io/`. The build uses **relative asset paths** (`"homepage": "."` in `package.json`) so it works from any sub-path without changes.
